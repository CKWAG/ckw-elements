    <div className="docs-subsection-description">

<div className="sb-unstyled">
  <div className="docs-section">
    <div className="docs-section-title">Interactive</div>
    <div className="docs-subsection-description">
      With <code>href</code> the whole card renders as one link. It uses shadow-s, lifts to shadow-m
      on hover and shows the focus ring (2px border-active, 2px offset) for keyboard users. The
      chevron in the header signals the link; turn it off with <code>showChevron={'{false}'}</code>{' '}
      only when the content already shows that the card is a link. Keep interactive cards short and
      do not put buttons or links inside them.
    </div>
  </div>
</div>

<div style={{ marginTop: '24px' }}>

    <div className="docs-subsection-description">
      Pass <code>icon</code> to CardHeader for a leading icon in a 40px tile (background-active,
      icon interactive-text), for example on KPI cards. Use the filled variant of an icon (e.g.
      bar-graph-filled), as in Figma. It is decorative and hidden with <code>aria-hidden</code>; the
      title carries the meaning. Icon, title block and chevron are vertically centred.

<div className="sb-unstyled">
  <div className="docs-section">
    <div className="docs-section-title">Accessibility</div>
    <div className="docs-subsection-description">
      CardTitle renders an <code>h3</code> by default. Set <code>as</code> to the level that fits
      the page outline, for example <code>as="h2"</code> directly below the page heading. An
      interactive card is a native link (<code>a</code>), so it works with the keyboard and its text
      becomes the link name; the chevron is decorative and hidden with <code>aria-hidden</code>. In
      Windows High Contrast the card gets a real border.
